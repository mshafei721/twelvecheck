01

First contact

  1. Value is obvious in five seconds

    Load the homepage cold. Can a visitor state who it is for, what it does, and why it matters without scrolling?

    Failure signal: the description fits several unrelated products.

  2. Headline matches the product

    Compare the headline with the actual first product screen, current release, or documented workflow.

    Failure signal: launch copy describes an older product or a feature the build does not expose.

  3. Primary action is unambiguous

    Follow the dominant button from the first viewport. Confirm its label predicts the destination and next step.

    Failure signal: “Get started” opens a demo, waitlist, generic page, or dead anchor.

  4. Mobile first screen holds

    Test a 390-pixel-wide viewport. Check the headline, main action, navigation, consent layers, and horizontal overflow.

    Failure signal: the action is clipped, covered, or pushed below avoidable chrome.

02

Core journey

  1. Sign up or log in works

    Use the public entry point and follow only ordinary account actions. Note redirects, validation, loading, and confirmation.

    Failure signal: a successful action returns to the same state with no explanation.

  2. First key action succeeds

    Complete the one action that demonstrates the product's promised value, using safe test data.

    Failure signal: the user reaches a dashboard but cannot find or finish the first meaningful task.

  3. Recovery path is clear

    Trigger one ordinary validation error or empty result. Confirm the message explains what changed and what to do next.

    Failure signal: a generic error, silent reset, or disabled action strands the visitor.

  4. Empty states guide forward

    Inspect new-account, no-result, and zero-item states encountered naturally during the journey.

    Failure signal: the page names what is missing but provides no next action or example.

03

Launch truth

  1. Pricing path is consistent

    Compare homepage, pricing, checkout, FAQ, and terms wording for price, billing period, limits, trial, and cancellation.

    Failure signal: a buyer cannot tell which public promise governs the purchase.

  2. Launch promise matches the build

    Check the launch listing and campaign copy against the current homepage and reachable product paths.

    Failure signal: product names, scope, integrations, or availability drift between surfaces.

  3. Confirmations explain next steps

    After signup, request, purchase, or submission, confirm the user sees status, ownership, timing, and the next action.

    Failure signal: success looks identical to failure or creates an unexplained waiting period.

  4. Obvious accessibility blockers are absent

    Keyboard through the public journey, zoom to 200%, inspect visible labels, and check meaningful image alternatives.

    Failure signal: focus disappears, controls have no name, or essential content becomes unreachable.

Capture enough evidence to reproduce it.

For every finding, keep the public URL, UTC timestamp, viewport, numbered journey step, expected result, observed result, and one screenshot. Label impact as P0 only when the launch journey is blocked; use P1 for material conversion friction and P2 for clarity or polish.
